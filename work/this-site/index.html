04 / 个人项目 2026.11

本站

你正在看的这个页面。没有后端、没有框架运行时，首屏的那片节点网络是手写的 Canvas。

角色
设计、开发、性能
技术栈
Astro · Canvas · CSS · TypeScript

背景

一个给自己用的站，用来把做过的事讲清楚。它同时也是我最近一次完整的技术决策：在一个内容极其简单的站点上，什么该做得重，什么该做得轻。

问题

  1. 01 不想用模板。作品集站本身就在替你做判断，一个用模板搭出来的作品集，等于第一句话就承认自己只会套模板。
  2. 02 不想为动效付出性能。首屏任何一处卡顿，都会在这次「演示」里变成减分项。
  3. 03 内容会长期变更。案例要能不断补充，但每次改文案不应该需要我重新部署一次架构思考。

做法

01

把框架整个去掉

用 Astro 输出纯静态 HTML 与 CSS，页面上唯一的 JavaScript 是首屏的 Canvas 和几百行的交互脚本。没有框架运行时、没有水合、没有客户端路由。

02

首屏那片节点网络

手写 Canvas：节点是圆角方块而非圆点，因为它们是流程图的隐喻；节点缓慢漂移，靠近时以细线相连，鼠标会轻微影响周围的节点。移动端与 prefers-reduced-motion 下直接渲染一帧静态图，不再启动动画循环。

03

动效只做在能看见的地方

滚动驱动的文字显影、数字计数与图片位移全部基于 IntersectionObserver 和 rAF，不使用动画库；离屏即停止，在低端机上降级为直接显示。

结果

静态
无服务端依赖
Canvas
首屏视觉
无第三方图形库
可降级
动效策略

最好的性能优化仍然是把代码删掉——这次我删掉的是整个框架。
