02 / WHOOSHPRO PTE. LTD. 2026.04 — 2026.10

多市场运营数据日报自动化

一家跨境品牌在九个平台经营，每天的数据散在九个后台里。人肉统计每天要花掉一整个上午。

角色
独立设计与开发
技术栈
Python · Playwright · 影刀 RPA · ShopifyQL · 飞书多维表格 API

背景

这家公司的生意分布在 Google、Facebook、Awin、Impact、Klarna、KOL、Klaviyo 和 Shopify 上。每个渠道有自己的后台、自己的口径、自己的导出按钮——而决策层每天早上要看一张把它们并起来的表。

问题

  1. 01 数据孤岛。九个后台之间没有共同主键，同一笔订单在不同渠道的口径还不一样。
  2. 02 统计靠人工。运营每天复制、粘贴、校对，四个小时起步，且错一个单元格整张表就失去意义。
  3. 03 没有沉淀。日报只存在于某个人当天的聊天记录里，无法回溯、无法对比趋势。

数据流

数据源
  • Google
  • Facebook
  • Awin
  • Impact
  • Klarna
  • KOL
  • Klaviyo
  • Shopify
  • +1
抓取与清洗
  • Python
  • Playwright
  • 影刀 RPA
  • ShopifyQL
落库
  • 31 列维度
  • 月份子表
  • 累加汇总

做法

01

先把口径定死，再写脚本

梳理每个渠道的核心指标定义，用 ShopifyQL 精确拉取销售 GMV、实收金额、订单数、折扣率、转化率、客单价，确保同一个数字在任何渠道都指同一件事。最终固定成 31 列业务维度。

02

让脚本替人点后台

用 Python 与 Playwright 编写浏览器自动化，配合影刀 RPA 处理那些需要登录态、验证码或页面上没有接口的环节。九个来源的抓取在同一次运行里串起来，失败的位置会单独告警，不会静默吞掉一天的数据。

03

直接写进团队已经在用的地方

深度集成飞书多维表格 API：跨月时自动创建月份子表，31 列数据逐日追加，累加汇总行自动计算并写入。团队不需要学习新工具，打开熟悉的表格就有当天数据。

结果

9 → 1
数据来源收敛为一张表
31 列

每日
自动运行并归档
含跨月建表

自动化真正难的不是抓取，是让九套不一样的口径在同一张表里讲同一件事。
